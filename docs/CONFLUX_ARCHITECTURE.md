# Conflux 架构与技术决策

Conflux 是小欣独立开发的本地优先 AI 聊天项目。开发流程统一见 [AGENTS.md](../AGENTS.md)。本文解释技术选择，不规定阶段审批或 PR 流程。

## 技术方向

使用 React、TypeScript、Vite 作为现有基础，Web/PWA 与 Android 优先共用业务代码；原生能力通过平台适配接入。后续是否调整技术栈由实际需求决定。

已有代码来自 Polaris，模块组织可复用，也可在解决实际问题时重构或替换。上游品牌、视觉、导航和架构偏好不限制 Conflux；界面以用户选择的主题和原型为准。

## 实现关系

- `src/ui/`：界面和交互；主题负责表现，共用消息、输入和操作组件承载功能。
- `src/app/`：会话、角色和功能流程的协调。
- `src/engines/`：请求、模型接入、工具、记忆及存储等可复用逻辑。
- `src/stores/`：应用状态与保存流程；持久资料通过现有数据层读写。
- `src/native/`、`android/`：平台能力适配。

这些是代码定位入口，不是不可修改的边界。改动前查清实际依赖，避免产生两份互相竞争的状态、消息记录或执行路径。

## 界面与主题

共享布局处理可用宽度、头像间距、键盘和长内容；主题保留自己的素材、配色、边框和装饰。功能在各皮肤中使用同一数据与动作。窗口缩小时应合理换行和收缩布局，保持文字可读、按钮可操作。

## 数据与请求

会话和角色归属、聊天历史及已有资料应能继续读取和保存。调整结构时同时处理旧数据；读取失败不能当成空记录覆盖保存。存储细节按需查 [数据手册](handbook/DATA_AND_STORAGE.md)。

模型接入按用户实际配置扩展，不限定 xAI/Grok 或某一种后端。上下文、工具注册、执行结果和用量显示保持一致；纯界面改动不扩展到请求或存储。密钥不写进仓库和日志，外发数据遵循用户配置及授权。

## 平台与可选服务

Web/PWA 和 Android 共用源码不代表设备自动共享数据。部署、同步、后台服务、ACP 或 Host 接入按具体任务实现，不作为每次开发的前置条件。修改应用标识、域名或存储路径时，要处理已有资料的读取方式。

来源和许可声明随代码保留。功能进度由当前实现与相关验证说明；历史规划不作为已实现能力，也不限制当前任务顺序。
