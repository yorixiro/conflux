# 请求详情（步骤 02）：验收说明

入口：设置 → 用量记录 → **本次请求拆解**。复用现有 `requestCollaboratorReply` 的请求准备审计和回复 `tokenUsage`，不引入新的上下文拼装器、记忆库、缓存开关或供应商调用。

## 看见什么

- 本地发送前估算：上下文总估算、配置预算，以及身份/人设、能力/工具、记忆、对话历史四类材料的相对体量。
- 结构数量：来源与保留的历史消息、按条数/预算/工具回执过滤的数量、选中记忆、摘要、召回候选、附件和可用工具数量。裁剪只影响本次请求材料，不删除原始聊天。
- 接口实际返回：输入、输出、缓存读取与未命中。`0` 与字段缺失分开表示；前缀符合缓存计划，不代表这轮已命中。
- 配置与账单不同：本地总估算不能替代服务商的 `usage`，更不能直接换算成价格；不同服务商的缓存计费语义也可能不同。

## 取数、隐私和生命周期

- `requestDebugRecorder.ts` 每轮追加一条仅内存的 `RequestInsightEntry`，同一 `requestId` 的准备、完成、失败状态覆盖更新，最多保留 12 轮；重载后消失。完整 debug 捕获仍需开发模式，不会因为打开普通用量页面而启用。
- `requestInsightRuntime.ts` **只构造数值、状态、角色/模型展示名和用量字段**；不保留聊天消息、系统提示词、记忆行、请求 JSON、endpoint、Key、工具参数或任何材料正文；不写 LocalData/localStorage。
- 历史总用量仍由已有消息持久化和原 `menuTokenUsage` 读取，临时请求拆解不充当第二份账本。

## 关注的验收边界

1. 新请求在非开发模式下可见拆解，但完整原始 prompt 不被启用；准备后完成只显示一条。
2. 实际 `cachedInputTokens: 0` 明确显示 0，缺失则显示「未记录」，请求准备计划不能伪装成实际命中。
3. 不能从临时投影恢复私人材料正文；刷新后该投影消失。
4. 320px 手机、720px 平板和 1440px 桌面进行实际视觉检查仍属设备/浏览器验收；没有调用任何付费模型来验证缓存效果。
