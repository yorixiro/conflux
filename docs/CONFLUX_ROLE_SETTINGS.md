# 角色设置：IB 对照与当前接线

参考：`yorixiro/InternalBeyond-Mobile`，commit `77c81cea65a5130ab0c9eed9142aa8a9c0dc1e51` 的 `index.html` 独立 API 配置页（`aset-*`）。该仓库使用 PolyForm Noncommercial 1.0.0；本次只核对功能行为，界面用 Conflux 既有组件实现，没有复制 IB 的 HTML、脚本、存储或请求实现。

## 入口与布局

- 聊天侧栏 → 对话库 → 当前角色名字右侧的设置按钮；手机抽屉与桌面共用入口。
- 通讯录只在侧栏对话库内展开，角色列表顶部可新建，点头像或名字进入聊天，右侧齿轮编辑对应角色；档案不再提供通讯录分类，角色设置页提供「返回聊天」。
- 个人资料展示当前聊天 AI 的头像、名字和简介，下方是可翻月的本地显示日历。资料依当前对话的归属角色读取，不展示用户称呼和用户头像，也不维护第二份配置。
- 对话库角色名字用于查看聊天 AI 资料，旁边的设置按钮保留；切换或新建角色统一使用其下方通讯录，普通聊天列表支持查看全部角色的对话。
- 设置页依次为「资料与人设 / API 与模型 / 记忆 / 主题 / 主动」。窄屏标签可横向滚动。
- 资料页用明确的输入标签显示名称、简介、自己的称呼、角色定位与关系；头像设置直接位于此页，不依赖聊天头像是否开启。人设、消息模板、调性和世界书使用原提示词组件。
- 内置小助手由产品向导规则维护，名称、简介、定位和线路会被规范化恢复。页面明确说明这一点，固定资料只读，并提供「新建可编辑角色」；不静默改写、替换或删除原角色与对话。

## 已有能力的对应关系

| IB 独立配置 | Conflux 当前设置与所有者 |
| --- | --- |
| 头像、昵称 | 资料页头像编辑器、角色名称；persona + asset 原动作 |
| 与 TA 的关系 | 「角色定位与关系」沿用 `purpose`；更完整的关系和行为写入人设，不增加第二个人设来源 |
| System Prompt | 资料页原提示词组件 → `compiledPrompt`，保留变量预览及内置角色编辑约束 |
| 服务商、模型、地址、Key | API 与模型 → 线路页；角色的 `advanced.providerId/modelOverride` 与 runtime 的 ProviderProfile 分别保存 |
| 接口预设 | 既有供应商模板与多线路管理，不另存一套密钥或模型配置 |
| 创意度、上下文条数、输出上限 | 生成参数 → temperature、contextMessageLimit、maxTokens；另保留 Top P |
| 流式、思考显示与预算 | 生成参数原开关与 thinkingBudget；不改变各厂商请求语义 |
| 图片能力、备用看图 | 线路页可选能力区，沿用 ProviderProfile 的能力与备用识图设置；明确属于共用线路 |
| 记忆设置 | 沿用原角色记忆页、文档与检索入口；不自动启用向量、生成摘要或调用模型 |
| 主动消息入口 | 原自动化规则页；不承诺 PWA 关闭后的后台定时可靠性 |
| 删除角色 | 原删除动作，保留历史对话的既有行为 |

线路页通过 `resolvePersonaProviderBinding` 显示本角色实际使用的线路和模型。修改角色模型不会切换全局默认线路；修改地址和密钥调用 runtime 原有 `updateProvider(id, patch)`，界面明确提示共用该线路的其他角色也受影响。密钥不进入 Persona 数据、日志、文档或分享内容。

## 仍未迁移的 IB 专有能力

本轮完成的是上述现有能力的整合，不能称为「IB 全部功能已迁移」。以下需要相应模块、请求协议或数据权限接通后再做：

- InternetBeyond 社交圈的加入、可见范围、发帖、评论、查看确认和配图权限。
- Blog、日历、动态等内容读取范围，以及各自的写入权限；群聊独立的历史读取条数。
- IB Auto Memory 的自主写入/编辑/删除、写入模式、静默和字数预算；现有 Polaris 记忆页不等同于该实现。
- IB 提示缓存的开关、Anthropic 一小时 TTL、服务商特定思考强度与分类器回退。没有把这些做成不生效的开关，也没有启用模型回退。
- IB 特有归档与独立接口预设交换格式；跨库导入仍需 staging、校验与明确提交。

这些项目没有新增假字段、默认开启权限或第二套存储。完整迁移仍按现有迁移矩阵推进。

## 验证边界

### 2026-10-28 紧凑模型选择修订

- 移除普通和克克资料页的大块模型表单。聊天输入框下方新增一行「模型 / EFFORT」下拉选择，绑定当前对话角色，与设置中正在编辑的其他角色隔离。
- 角色的「API 与模型 → 线路」页提供模型拉取/刷新、模型选择、手填模型和思考强度。全局 API 设置仍可拉取线路模型；同一连接的列表在当前会话内共享，关闭设置后聊天下拉也能选择。更换地址、协议、路径或密钥时失效，不持久化发现缓存。
- 角色 API 页提供线路思考能力开关；明确它影响共用线路的角色。模型和强度选择仍仅保存到当前角色。
- 官方 DeepSeek V4 的 Chat Completions 和 Responses 适配 low/high/max；沿用原角色思考预算字段保存选择，不新增存储或迁移。旧版 DeepSeek 和非官方网关不猜测能力。协议依据：https://api-docs.deepseek.com/guides/thinking_mode/ 。
- 验证：`npm run verify` 的主类型检查、额外类型检查与 Worker 类型检查通过；全量测试初次仅遇到既有主题图片断言及一项需要随新 DeepSeek 行为更新的断言。更新该请求断言后，8 个相关测试文件共 108 项通过；`npm run build` 通过。浏览器与 Android 真机未验收，未调用真实模型服务。

### 2026-10-28 初版资料栏模型与思考深度（布局已由上面的修订替代）

本次集成以手机 `keke-theme-preview` 对应的 `4fd2c49` 为基线，发布到独立分支 `feat/keke-profile-model-effort`。完整保留四个克克主题提交；普通资料栏和 `KekeSidebarProfile` 共用同一套模型控件，克克资料页在备注区后、主题切换及日历之前显示，沿用两套纸张主题配色。

- 当前聊天 AI 的资料栏新增模型下拉、拉取/刷新、手动模型 ID、跟随线路模型和思考深度。模型与深度分别沿用 Persona 的 `advanced.modelOverride` 和 `advanced.thinkingBudget`，仅更新该 AI；不改变全局线路或其他 AI。

- API 设置增加独立的拉取/刷新按钮。与资料栏共用发现 hook；线路、地址、协议、路径或密钥变更时清空列表并取消旧请求，卸载时取消请求。刷新失败保留最近成功列表，显示可重试提示，不回显上游响应正文。列表为临时状态，所选模型由既有 Persona/Runtime 保存流程持久化。
- `npm run build` 及相关模型发现、角色绑定、Responses、协议一致性、Persona 持久化测试通过。新增回归覆盖指定角色保存/回读、其他角色不变、下一请求携带所选模型和 high、恢复默认后省略强度。
