# Conflux 独立化迁移与旧工程替换清单

目标：建立不带 GitHub fork 关联、独立发布和维护的 Conflux 项目；旧品牌、旧 UI、过时文档与不合理实现逐模块退出。**不以保留旧 UI/技术习惯为约束**。

状态：迁移规划；新独立仓库尚未创建，以下验收未完成。

## 独立仓库创建前必须确认

- **源码基线**：以最新经过核对的 `feat/keke-devin-acp-preview-20261030` 提交为代码候选，不使用尚未包含各项开发成果的 `main`。
- **本地状态**：对比手机 Termux 的 `git status --short`，确认没有需要带走但尚未提交的文件；临时 stash 与 patch 先核对是否含有独立工作。
- **现有功能**：克克原始美化、其他主题、聊天/角色/对话库、PWA、Android、ACP 集成代码、记忆相关未合并分支逐项盘点。
- **存储兼容**：PWA origin、service worker、localStorage/IndexedDB/SQLite、Android appId 与导入导出，必须决定新安装路径如何读回已有资料。
- **新仓库**：在 GitHub 建一个**新独立仓库**（不是再点 Fork），把经过验证的 Conflux 源码推过去；新项目的主分支必须指向经核对的开发成果。当前仓库保留为迁移回滚点。

## 旧痕迹的处理分类

| 类别 | 动作 | 说明 |
|---|---|---|
| 产品名称、README、开发指令 | 直接改成 Conflux | 旧设计规则不再作为开发要求 |
| 网页标题、PWA 图标、品牌文字 | 逐个替换 | 使用 Conflux 自己的资源 |
| 旧主题、废弃 UI 和装饰 | 先查引用再删 | 不挪动当前生效的美化 |
| 旧代码命名、包名、工具脚本 | 按依赖链分阶段改名 | 不能把运行依赖、存储键、接口一次性全局替换 |
| 会话/角色/数据层逻辑缺陷 | 独立功能工单重构 | 新实现需保证记录归属、持久化和回归 |
| 不再使用的后端、样例和文档 | 先确认无人引用，再分批删除 | 不向新仓库带无用模块 |
| 第三方版权与许可文件 | 保留适用声明 | 与 UI/产品身份分离，参见 PROVENANCE.md |

## 分阶段实施

**P0 — 当前开发版验收与目录盘点**：记录最新 SHA、未提交改动、stash、旧分支独有改动；完成关键功能的最低验收。

**P1 — 独立仓库**：建立独立新库并推送开发快照，确认文件/提交一致；切换部署和手机远端之前先验证可独立克隆与构建。

**P2 — 品牌、资源和旧 UI**：清除旧产品文案、旧图标和废弃视觉模块；让当前 Conflux 主题成为默认产品视觉。此阶段不重写数据库。

**P3 — 架构去遗留**：按领域审计聊天/角色、会话管理、请求、工具、数据层和 PWA；识别可删除代码与值得替换的复杂抽象，分别做定向测试和替换。

**P4 — 持久化与多端兼容**：若重命名内部存储键、Android 包标识或改变 PWA 域名，先明确老数据如何迁移或导入，再发布新版本。

**P5 — 正式切换**：核对新仓库代码、源码许可、构建和 Android 平板体验，旧 fork 再决定归档或其他处理。禁止迁移中途先删除旧仓库。

## 验收结果记录

每一阶段应记录：实际 commit、变更文件、删除/保留理由、运行的测试、未解决问题、恢复路径。不接受“全局替换 Polaris 为 Conflux”作为架构清理完成的证明。
