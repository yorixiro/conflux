# Conflux UI 布局规范 / Layout Contract

版本：1.0 · 2026-10-30  
适用：React/TypeScript 共用界面，Web/PWA、Android 手机及平板。  
**状态：设计基线，当前尚未完成代码级接入或设备验收。** 本文件本身不改变 UI，不宣称现有界面全部符合规范。

## 目标与优先级

Conflux 允许非常不同的视觉主题（克克贴纸/波点、极简、玻璃等），但统一同一组件的操作语义和基本可用性。

优先级从高到低：

1. **不可覆盖的交互约束**：键盘弹出不能挡住输入；控制可触达；内容不能横向溢出；数据与会话归属不能因为换肤改变。
2. **布局结构约定**：导航、对话区域、左右抽屉、输入区的定位和响应式行为。需变更时按独立功能工单审查。
3. **默认尺寸档位**：以下固定数值。新增组件必须从档位中选取；特殊偏离要给出原因。
4. **主题视觉与可控变体**：主题可以调整装饰、形状、内边距、抽屉宽度或专门的卡片布局，但不得覆盖 1 的约束。

尺寸单位在 Web 端为 CSS px；原生 Android 需要在真实设备核对物理触控目标和系统缩放。不要把设计稿像素与手机硬件像素直接等同。

## 固定尺寸档位（默认）

| 角色 | 默认值 | 约束与说明 |
|---|---:|---|
| 细节间隔 | 4px | 图标与标签之间 |
| 常规间隔 | 8px | 相邻小控件 |
| 组件内部间距 | 12px / 16px | 小卡片 / 普通卡片 |
| 区块间距 | 24px | 不同功能区 |
| 常规可点击区域 | 至少 48×48px | 视觉图标可只有 18–22px，点击区域不能跟着缩成 18px |
| 普通单行输入/选择器 | 48px 高 | 统一控制行高 |
| 标准操作按钮 | 48px 高 | 紧凑外形可使用 40px 视觉形状，外部命中区域仍须满足 48px |
| 设置项列表行 | 56px 最小高 | 多行文案按内容扩展 |
| 顶部导航栏 | 56px 基础高 | 系统安全区域另外计算，不能挤压标题或按钮 |
| 底部导航 | 56px 基础高 | `env(safe-area-inset-bottom)` 另外计算 |
| 聊天输入文本区域 | 48px 初始最小高 | 多行自适应，默认最大 160px；文字不被语音图标盖住 |
| 普通卡片内边距 | 16px | 紧凑变体 12px，内容型变体 24px |
| 聊天内容阅读列 | 最大 760px | 窄屏占满可用宽度；特殊沉浸主题可申请不同阅读列 |
| 用户气泡最大宽度 | 对话可用列的 80% | 高度由内容决定，不允许统一固定高度 |
| AI 气泡最大宽度 | 对话可用列的 90% | 代码、表格应支持横向内部滚动，不撑破页面 |
| 侧栏默认宽度 | 360px | 不超过视口剩余安全间隔；左右同类抽屉必须一致 |
| 克克双侧抽屉宽度 | `min(388px, calc(100vw - 18px))` | **保持现有原型视觉的已知基线**，不要强制缩回 360px |

这些是 **Conflux 项目明确选定的尺寸基准**，不是声称所有平台存在唯一“官方标准”。触控目标和可读性为设计约束，具体卡片比例是本项目规范。

## 响应式与容器规则

- 以现有 `appLayoutSurface` / 应用 shell 的布局判断为唯一权威，不新建一套可能冲突的断点机制。
- 验收至少覆盖 320px 窄手机、720px 平板以及 1440px 桌面宽度；还要覆盖横竖屏和虚拟键盘弹出。
- 页面级容器可 `width: 100%`；可读文本使用 `max-width`；交互抽屉使用 `min()` / `max()` / `clamp()` 等流式约束，而非把设计稿宽度硬塞进小屏幕。
- 所有弹层必须考虑 `100dvh`、安全区、滚动区 `min-height: 0`、文本换行、屏幕缩放和长模型名。
- 必须做到：抽屉内容不横向平移；底部输入和底栏不重叠；页眉按钮不遮挡标题；二级面板滚动不穿透背景。
- 控件“视觉尺寸”与“点击热区”分开：克克主题 30px 的可爱胶囊可以保留，但点击区域要足够大且不互相抢点击。

## 新主题接入协议

**坚决不把任何新主题的截图尺寸直接复制为产品全局尺寸。** 每个新视觉原型按以下边界接入：

1. 先确认复用哪一个真实 React 组件和业务动作；没有对应组件时，声明新布局变体，不复制新的聊天、角色或存储引擎。
2. 原样保留视觉素材和原型 CSS，放进独立主题目录；对真实 DOM 的映射仅写在主题适配层。
3. 大小、间距如果不同，主题适配层覆盖已定义的语义尺寸变量；绝不大量写全局 `button`、`input`、`aside` 强制样式。
4. 如果新主题需要新的卡片排列结构，用明确的组件变体（例如 `compact` / `editorial`），不靠级联覆盖硬凑，也不让主题改变按钮的行为。
5. 回归检查：默认主题、旧克克主题、新主题至少在窄手机与平板都能导航、发消息、打开侧栏、切换角色；只检查与本次改动有关的交互和布局，不无故做昂贵的全量模型调用。

**尺寸变量的规划接口（尚未接线）：**

```css
:root {
  --cf-space-1: 4px;
  --cf-space-2: 8px;
  --cf-space-3: 12px;
  --cf-space-4: 16px;
  --cf-space-6: 24px;
  --cf-touch-target: 48px;
  --cf-control-height: 48px;
  --cf-topbar-height: 56px;
  --cf-bottom-nav-height: 56px;
  --cf-chat-input-min-height: 48px;
  --cf-chat-input-max-height: 160px;
  --cf-card-padding: 16px;
  --cf-drawer-width: min(360px, calc(100vw - 18px));
}
#chat:has(.keke-themed),
#chat:has(.keke-original-topbar) {
  --cf-drawer-width: min(388px, calc(100vw - 18px));
}
```

以上 CSS 只是变量命名和预期的用法示例，**不是可直接贴到现有页面的补丁**。后续应在 `src/styles/layout-tokens.css` 放真实变量，再逐个将相关组件改为读取它们，避免一次性重写 `src/styles/tokens.css`、`src/ui/keke-original/adapter.css` 和所有壳组件。现有左侧栏与右侧快捷设置都使用 388px，优先保持现状。

## 每次新增或移植组件的验收

- 有明确用途和语义尺寸档位，而不是随意写 `height: 37px`、`width: 283px`。
- 同类功能按钮尺寸和操作位置一致；重复入口有具体理由。
- 文本自动换行；按钮不会压住文字；长 AI 名称与模型名不会撑破容器。
- 宽度 320 / 720 / 1440 下没有横向页面滚动、抽屉溢出、键盘遮盖。
- 不改聊天历史、角色 ID、会话 ID、数据归属、API/ACP、主题存储。
- 新主题关闭后，原主题外观和功能恢复完整。
- 报告实测设备和执行过的测试；没跑过的不得写通过。

## 本轮实施限制

本规范先作为评审依据，不立即统一替换现存 388px、44px 等值。要落地需单独做小范围 CSS 变量接线与设备验收。**不得借“统一尺寸”重新设计克克原型、移除贴纸或缩窄纸张侧栏。**
