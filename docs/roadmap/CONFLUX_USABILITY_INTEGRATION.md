# Conflux · 六项操作整合路线图

状态：规划中 · 2026-10-30  
仓库：`yorixiro/conflux`  
**这是总路线图，不是“一次做完六项”的开发工单。** 单项落地再创建 `docs/work-orders/WORK_*.md`，一项一分支、一项一 PR，由 Work 执行；PR 在用户验收前不合并。**每轮开发开始前读取本文件，结束前必须回写真实状态与工单记录，不能长期停留在「待开发」。**

## 目标

让日常操作不需要跨多个页面来回寻找；不扩大前端功能栈，不破坏已经做好的克克主题、聊天、记忆、PWA、Android、ACP 和数据。

| 顺序 | 项目 | 状态 | 最小范围和验收 |
| --- | --- | --- | --- |
| P0 | **AI 通讯录 × 会话管理** | 待开发 | 打开某个 AI 后统一入口：继续对话、新建该角色会话、查看**该角色**历史、编辑角色。新建角色先编辑草稿，确认后才落盘；空白取消不生成“未命名”。会话必须按 role ID 归属，不能串房。**不恢复全局最近对话页面**。 |
| P1 | **当前 AI 设置 × 模型选择** | 待开发 | 当前 AI 的模型/线路、角色提示词、记忆、工具、语音在同一操作流；全局 API、密钥、主题、存储仍属全局设置。避免重复保存同一配置，不改模型 API 协议。 |
| P2 | **聊天消息 × 心弦收藏** | 待开发 | 消息菜单直接“收藏到心弦”，可存为信笺、时光片段或记忆候选；记录真实来源会话/消息 ID；从收藏返回消息。记忆候选先确认再保存，不自动污染记忆。 |
| P3 | **统一搜索入口** | 待开发 | 按对话、记忆、收藏和工坊分域搜索；复用已有检索，不新建平行索引或收费 API；结果能定位原数据，处理未加载历史和孤儿引用。 |
| P4 | **主页操作工作台** | 待开发 | 主页优先“继续当前对话/共读/最近珍藏/实际待办”；清理重复的角色设置、空白待办与空白日历入口。无真实数据不编假卡片。不能为首页重做导航。 |
| P5 | **数据与费用管理** | 待开发 | 备份、恢复、数据位置、占用、Token 消耗、缓存命中和 API 余额错误归类；区分估算与实账。备份恢复使用现有事实源，不修改用户本地资料。 |

## 共同交互原则

- **对话**是 AI 联系人和会话入口；**心弦**是收藏、时光、信笺、共读和记忆图谱；**工坊**是创作与文件；**设置**是全局配置。
- 每个重要动作应能从它的**所属上下文**完成，不复制第二份业务数据，不用增加导航标签来回避布局问题。
- 打开已有会话必须同步当前 AI 身份；不存在默认新建空白角色的副作用。
- 新功能应使用现有 UI 布局规范 `docs/UI_LAYOUT_SPEC.md`，保留主题美化的独立适配方式。

## 开发与验收

- 每项启动前核对最新实际开发分支、未提交改动和 PR 依赖，不以旧 `main` 为基础；先遵循 `AGENTS.md`。
- 每项一个明确范围的 Work 工单，在 `docs/work-orders/` 中维护；工单注明实际基线、修改目标、验收动作、禁止修改的模块。
- 测试遵循“定向审查 → 必要定向测试 → 一次类型检查”原则。不跑无意义的冒烟、全量回归、发布门禁、哈希检查或收费 API 测试；必要构建必须明确目的。
- 交付 PR、Commit SHA、修改文件、实测结果及 Termux/Android 平板操作步骤。未经验证不写已通过。

## 每轮 Work 必须回写进度（交付条件）

**开工时**：先读取这份路线图、对应的 `docs/work-orders/WORK_*.md`、最新 PR 与基线提交，核实上轮实际完成项和遗留问题。不可因为表格尚未更新就当成全新项目，从头重做。

**收尾时**：在对应 PR 中一并修改本路线图和具体工单的进度段落，按实际情况记录：

- 状态只用「待开发 / 开发中 / PR 待验收 / 已验收 / 阻塞」；**提交代码或开 PR 只能标成「PR 待验收」，不能自动标「已验收」**。
- 最后一次更新的日期、PR 链接、真实 Commit SHA、完成的功能、未完成问题、定向测试结果和 Android 平板是否实际验收。
- 如计划发生调整，更新本路线图的任务范围、依赖和下一步，不留陈旧的文字。

**跨分支同步要求**：修改只存在于功能分支的文档，下一轮从共享开发分支启动时看不到。因此 PR 创建后，应将**不涉及运行代码的进度摘要**同步到共享开发分支的这份路线图；如不能直接更新，建立独立文档 PR 并明确说明尚未同步。功能代码继续保持独立 PR，不擅自合并。

**提交前核对**：检查最终变更中确实含有进度更新。若验收失败或任务未完成，明确记录「阻塞 / PR 待验收」与原因，不得以“已完成”掩盖问题。不运行额外门禁/冒烟/哈希来验证文档更新。
