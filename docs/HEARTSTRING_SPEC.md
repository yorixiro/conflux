# 心弦（Heartstring）产品边界与落地顺序

状态：2026-10-30 第一阶段接入。当前已有收藏册与基于真实角色数据的记忆来源概览；信笺、时光、完整共读仍在规划。不要把阶段计划当成功能已验收。

## 五个空间

1. **收藏册**：继续使用已经实现的 ArchiveAlbumShelf / 3D Folio。保存照片与图像卡片，沿用原 ownerCollaboratorId 和资产存储，不重新建库。
2. **信笺**：以后存私人信件、收发对象、正文、日期、草稿和归档状态。与聊天消息区分；只有显式收藏的文字才进入这里。
3. **时光**：主动收藏的纪念日、片段、图片与信件；不是把所有聊天历史自动排列成时间线。未来应有可编辑时间节点和来源链接。
4. **共读**：选择有使用权限的本地书籍或文档，共用进度与书签，绑定一个 AI 和对应对话，通过章节定位和明确引用对话；批注、页码/位置、选中文本和书本 ID 应能长期恢复。共读会话及内容存储尚未接入，当前 UI 明确标注未开放。
5. **记忆图谱**：让用户看到记忆在何处、由谁拥有、来自哪一层，再通过现有 MemorySettingsTab 操作真实记忆。第一期图只表示「当前角色 → 条目 / 文档 / 摘要 / 索引」四类**来源归属关系**及数量，不推断因果或语义联系。

## 记忆图谱的正确技术边界

- 读取 usePersonaStore 的现有 PersonaMemorySettings，不引入平行 memory 数据库。复用 MemorySettingsTab 进行添加、更正、删除、参考文档和摘要管理。
- 文档内容可能尚未加载：只有元信息可用时不得声称已经读取全部正文；图的文档节点数量仅是已登记文档数。
- 向量索引数量来自现存 vectorIndex.indexedChunkCount，仅展示登记状态，不自动调用 Embeddings API、刷新索引或改变模型供应商。
- 第二阶段若加入语义节点/边，必须保存真实的 provenance、来源 ID 与检索证据。不得通过关键词或猜测关系把相关联误报为事实。
- 编辑/删除采用现有存储写入和确认机制；任何新图谱编辑器需要可回滚和记录纠错来源。

## 共读的最小可交付功能（后续单独工单）

- 书籍导入与持久存储：优先本地 TXT / EPUB / PDF 等用户授权内容，保护原书排版，适配 Android/PWA
- 可恢复阅读进度：按书籍 ID、定位、章节记录，可在手机/平板恢复
- 选中原文→写批注 / 与指定 AI 讨论，消息含书籍 ID、来源定位和有界摘录
- 阅读会话绑定现有 Conversation ID，不建立新聊天系统；切换 AI 不串房
- 不上传整本书到模型；按用户明确选取的片段和阅读上下文发送，并提示成本
- 断电、离线、服务重启和数据导出均须验收；定向测试优先，全量回归最后一次

## 主题与布局

心弦有自己的五标签视觉层，但内容组件必须保留已有数据能力；美化原型不应覆盖状态和存储。横向标签在小屏幕可以滚动，但每一项点击区域至少 48 CSS px 高。3D 收藏册按需渲染；记忆管理按需加载。
