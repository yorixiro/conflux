## 目标

以教程实际演示为主要参考，独立创作一个可运行的 **Galaxy/星系生成艺术实时互动场景**，让用户直接在 Web/PWA/Android 平板上感受动态视觉。参考用户的偏好：TouchDesigner、Three.js、GPU 粒子、空间感、流动和高质量的交互数字艺术。应有真实的深度、运动规律与可控的视觉参数，而非 GIF/截屏、静态 CSS 装饰或忽略演示的擅自重构。

## 执行要求

1. 阅读 `AGENTS.md`、`docs/UI_LAYOUT_SPEC.md`、当前 Three.js 的渲染和清理模式，检查工作区状态及当前 HEAD。**基于已存在开发成果的预览分支，而非旧的默认 `main`**。
2. 使用 Work 的浏览器亲自访问教程链接，辨认真实作品的视觉特征、动画速度、相机/交互方式、星系的生成机制及可选调节项；记录与截图说明的区别。若无法访问，注明参考未核实，先实现明确标注为“原创近似版”的独立预览；不要声称精确复刻。
3. 使用项目已有的 React、TypeScript 和 `three@0.186.0`，独立实现实时 3D/粒子/Shader/TSL 场景。渲染方式由实际参考和设备能力决定，不强制引入没必要的新依赖。发光、层次、视差、动感和色彩编辑以参考作品的实际表现为准。
4. **只新增隔离的实验预览**（开发专用入口或独立页面），并提供一个可直接访问的预览路径。**不得插入当前 Conflux 首页、聊天背景、克克主题、心弦记忆图谱或 Three.js 收藏册。** 第一轮不合并，也不改动聊天业务、数据库、Service Worker 或 ACP。
5. GPU/触控生命周期：响应容器尺寸变化与 DPR，屏幕隐藏/离开预览时暂停，卸载释放 RAF/renderer/geometry/material/texture/render targets/监听器；Android 性能不足时可以降低采样/粒子密度，不通过降低所有平台画质来敷衍。若 WebGL 不可用提供清楚的回退状态。
6. 演示可以有少量明确的调节功能，如颜色/辉光/粒子密度/速度/暂停（依据参考和技术可行性），不能用大量表单取代视觉本身。
7. 开独立 feature 分支和 PR，交付可预览代码。不要合并 PR、强推、重置或删除历史分支。

## 验收与成本控制（**严格执行**）

- **只做定向审查**：核对本次场景真实 Three.js 实时渲染、交互、resize、RAF/资源清理、WebGL 失败分支与入口隔离。对确定要改的纯逻辑/生命周期代码可跑对应 Vitest 文件；视觉使用人工观察和必要的截图/短视频说明。
- **设备检查**：有浏览器时在 320px 手机、约 720px Android 平板、常规桌面宽度检查没有错位/掉帧或触控失效；可用设备不足则标记未测，不能假称通过。把 FPS、DPR、粒子密度等实际参数写出来，未测的不写数字。
- **执行上限**：所有代码收尾后最多运行一次 `npm run typecheck`；仅当确实需要验证产物时最多运行一次 `npm run build`。不要因非相关旧错误反复重跑。
- **禁止**：`npm test` 全量、`npm run verify`、`npm run publication:gate`、例行 `npm run test:pwa`/无关冒烟、全量 E2E/发布门禁、哈希/快照矩阵、与本任务无关的性能回归、收费模型/API 调用、无意义代码扫描循环或重复安装依赖。
- 不复制无许可来源代码/素材；若参考站说明源代码许可，遵守声明。可以学习技术方案后独立实现。
